# 2026-10-28

## make-cert 项目定位分析（未写代码，仅设计分析）

- 项目现状：create-next-app 脚手架，Next 16.4.3 + React 19.3 + Tailwind 4，`next.config.ts` 已启用 `cacheComponents`、`partialPrefetching`、`experimental.agentFeedback`；依赖中无任何密码学库。
- 关键结论：浏览器**无法**签发被公信信任的证书（根证书在系统/浏览器信任库）。因此产品定位应为「私钥不出浏览器的证书构造器 + CSR 生成器」，而非 CA。
- 能力边界：可做 → 密钥生成、自签名 X.509、CSR(PKCS#10)、PEM/PKCS#12 打包、证书解析校验；不可做 → 公信签发、域名校验、信任库安装、吊销分发。
- 推荐技术栈：`@peculiar/x509`（基于 WebCrypto，支持 X509CertificateGenerator / Pkcs10CertificateRequestGenerator）+ asn1js/pkijs 兜底，PKCS#12 走 pkijs 或 node-forge；Next `output: 'export'` 静态导出 + client-only + Web Worker，保证可离线、可证明零上传。
- 合规要点：CA/B SC-081v3 —— 2026-03-15 起公信证书最长 200 天，2027-03-15 起 100 天，2029-03-15 起 47 天（DCV 复用期 2029 降到 10 天）。自签默认有效期建议 ≤397 天并做上限校验。

## 第一版实现（方向 A：自签名 + 内建 CA）

- 技术栈落地：`@peculiar/x509@3.1` + `asn1js@4` + `node-forge`（仅 PKCS#12）+ `reflect-metadata`（x509 v3 依赖 tsyringe，浏览器/Node 都必须先 import 该 polyfill，否则报 "tsyringe requires a reflect polyfill"）。
- `next.config.ts` 改为 `output: "export"` 静态导出，同时删除 `cacheComponents` 与 `partialPrefetching`——两者与 export 互斥（报 `Invariant: PPR cannot be enabled in export mode`）。产物在 `out/`。
- 代码结构：`lib/cert/{pem,keys,issue,parse,validate,pkcs12,snippets,types}.ts` + `components/{cert-studio,result-panel,inspector,ui}.tsx`。
- 关键实现细节：
  - CA 私钥导入需按 CA 证书公钥算法决定 importKey 参数；PKCS#1/SEC1 要用 asn1js 手工包成 PKCS#8。
  - `SubjectAlternativeNameExtension` 的 URI 类型常量是 `"url"` 不是 `"uri"`，否则 TS 报错。
  - AKI 用 CA 证书自带的 SKI keyId 构造，不要传 `cert.publicKey`（类型是 peculiar 的 `PublicKey`，非 `CryptoKey`）。
  - 根 CA 不生成 SAN；CA 模式隐藏 SAN 编辑器，CN 默认改成 "Local Root CA" 并支持回切还原。
  - 序列号 16 字节随机且最高位清零；notBefore 回退 5 分钟。
- 验证方式：`playwright-core` + 本机 Edge（无需下载浏览器）跑 E2E，再用 `openssl x509 / verify / pkcs12 -info` 复核。自签名、CA→叶子链（`openssl verify` OK）、ECDSA、PKCS#12 均通过；ECDSA 的 p12 按钮按预期禁用（node-forge 只支持 RSA）。
- 教训：Tailwind 里 `controlClass` 含 `w-full`，通过 className 传 `w-[92px]` 会失效（同优先级后者未必胜出），改用固定宽度 wrapper 包住 Select。

## 第二版：本地 CA 库 + 证书链校验

- `lib/ca-store.ts`：IndexedDB（库 `make-cert` / 表 `ca`）存根 CA，主键用证书 SHA-256 指纹，重复保存自动覆盖。**明文存私钥**，与 mkcert 存 `~/.mkcert` 同一信任假设，UI 明确提示「未加密、清理浏览器数据会丢失、请保留 PEM 备份」。
- `lib/cert/chain.ts`：`analyzeChain(pems, now)` 从叶子向上按 subject==issuer 名匹配找签发者，逐级 `cert.verify({publicKey})`；同时检查 AKI/SKI 是否一致、签发者是否 CA:TRUE、每个节点的有效期、以及未被使用的多余证书。签名分三态 `valid | invalid | unknown`——找不到签发者时必须是 unknown，不能谎报「签名无效」。
- UI：根 CA 结果卡新增「存入本地 CA 库」；叶子模式顶部出现「从本地 CA 库选择」下拉（含已过期标记 + 删除），选中即回填 cert/key，这就是一键续签路径。解析器支持粘贴多张 PEM，底部渲染链视图（节点序号 + 叶子/CA/自签名顶端/签名状态 + 问题列表）。
- 坑：渲染期调用 `Date.now()` 会触发 `react-hooks/purity` 规则报错，改用模块级 `PAGE_LOADED_AT` 常量做粗判断。
- 验证：playwright 脚本跑通「生成 CA → 存库 → 切换模式 → 下拉选用 → 签发叶子」，再把叶子+CA 粘进解析器得到「完整 · 2 级」，只粘叶子得到「不完整」+「缺少签发者 CN=Local Root CA」。测试后已卸载 playwright-core。

## 第三版：从本地文件导入 CA

- `lib/cert/import.ts`：`splitPemMaterials` 拆证书/私钥（支持 PKCS#8、PKCS#1、SEC1）；`describeCaBundle` 选最匹配的一张（评分 = CA:TRUE 优先 + 私钥配对优先）；`readPkcs12` 用 node-forge 解 .pfx/.p12。
- **私钥配对校验**：导入私钥后签一段固定文本，再用 `cert.publicKey.export()` 得到的 CryptoKey 验签。不配对必须当场报错——签发本身不会失败，但链一定校验不过，属于最难排查的沉默失败。
- 支持证书和私钥分两个文件导入：缺哪一半就与已填字段合并后再判定，符合「下载下来就是两个文件」的真实习惯。
- 验证：用 openssl 生成独立的 CA（含 PKCS#1 私钥、以及 `-export` 的 pfx），导入后签发叶子，`openssl verify -CAfile ca.crt leaf.crt` 返回 OK；错口令、错配私钥均能给出明确报错。

## 文案收敛：去掉非功能性描述

- 用户要求移除「私钥不出本地」这类安全营销式表述。已清理：页头绿色徽章、参数卡「本地运行」徽章、三处「私钥不会离开/不经过网络/不发网络请求」、私钥 Tab 的泄露警告条、CA 区「私钥只在本机使用」、解析器空态的「装了证书还报错」说教。
- 保留的是**可操作信息**：时间按本地时区、RSA 4096 较慢、CA 库清理浏览器数据会丢、公网证书需 CA 签发（范围说明）、导入配对校验结果。
- 判断标准：这句话能否帮用户少犯一次错？能 → 留；只是让产品显得更安全 → 删。

## 核验「是否纯前端」

- 结论：运行期是纯前端。`app/` 只有 page/layout/css/favicon，无 route handler、无 server action、无 middleware；业务代码里唯一的 `http://` 是 IPv6 字面量校验用的 `new URL()`，不发请求。
- 实测方法（可复用）：用 node 起一个只服务 `out/` 的静态服务器（3100），playwright `page.route("**/*")` 拦截所有非 localhost 请求并 abort，页面仍能正常生成证书，外部请求数 **0**，本地请求 12 个（HTML/JS/CSS/自托管 woff2），无控制台报错。
- `next/font/google` 的 Geist 在**构建期**下载并自托管进 `_next/static/media`，运行期不访问 Google；但 `npm run build` 需要网络（未缓存时）。
- 修正了一处不实描述：静态导出的资源路径是绝对的 `/_next/...`，**不能双击打开 out/index.html**，本地预览需 HTTP 服务（`npx serve out`）。README 与 next.config 注释已改。
- 顺手把 `@types/node-forge` 从 dependencies 挪到 devDependencies。
